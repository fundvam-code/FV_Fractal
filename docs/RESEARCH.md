## 2. Оптимизация ограничителя просадки

Полный перебор 60 комбинаций: `InpMaxDrawdownUSD` 10…150 с шагом 10, `InpDrawdownBasis` 0/1,
`InpDrawdownForceClose` 0/1. Остальное зафиксировано.

- **База 0 (от пика эквити) не работает:** блокирует торговлю после первой же просадки от
  максимума, 1–10 сделок за период, критерий равен 0.
- Лучшие комбинации (база 1, дневной убыток):

| MaxDrawdownUSD | ForceClose | Прибыль | PF | Сделок | Просадка эквити | Критерий |
|---|---|---|---|---|---|---|
| **60** | true | 539 | 1.32 | 150 | 27.6 % | **242** |
| 60 | false | 561 | 1.33 | 136 | 27.7 % | 239 |
| 70 | true | 437 | 1.25 | 139 | 31.6 % | 166 |
| 70 | false | 499 | 1.29 | 137 | 35.8 % | 165 |
| 50 | false | 444 | 1.26 | 130 | 32.7 % | 157 |
| 30 (прежний) | — | 458 | 1.29 | 129 | 34.1 % | 155 |

- Порог 60 лучше прежних 30 по всем показателям. Соседние значения 50 и 70 держатся в том же
  диапазоне, то есть это устойчивая область.
- При порогах 90–150 без принудительного закрытия часть проходов отсекается критерием из-за
  доли прибыли от одной сделки, остальные вырождаются в «ограничитель не срабатывает».
- Выбран набор: **60 / база 1 / ForceClose = true**.
- Параметры трейлинга и безубытка в этом прогоне не оптимизировались.

## 4. Профиль сделок и безубыточный винрейт

Механика текущего набора такова, что результат определяется винрейтом.

- Победа: стоп переносится на +0.15 ATR (параметр `lock`) и выбивается там. Средняя прибыль
  около 14–19 USD.
- Убыток: стоп 0.5 ATR, средний убыток около 45–65 USD.
- Тейк практически не срабатывает; трейлинг (175 % ATR) шире тейка (150 % ATR) и не включается.
- Безубыточный винрейт при таком профиле 72–77 %. Реальный: 74–82 % с фильтром тренда,
  70–74 % без него.

`InpBreakevenLockAtrPercent` (15) больше триггера `InpBreakevenAtrPercent` (10): оптимизатор
упёрся в границы диапазонов (нижняя у триггера, верхняя у lock). Это признак оптимума на краю,
диапазоны стоит пересмотреть и добавить условие `lock < trigger`.

## 8. Z-score

Z-score в отчёте тестера проверяет случайность порядка побед и убытков. Считается число
серий R подряд идущих одинаковых исходов и сравнивается с ожидаемым при случайном порядке:

```
Z = (N·(R − 0.5) − P) / √( P·(P − N) / (N − 1) ),   P = 2·W·L
```

где N — число сделок, W и L — числа побед и убытков. Расчёт по сделкам воспроизводит значения
отчётов тестера.

- **Отрицательный Z** — серий меньше случайного: победы и убытки идут группами.
- **Положительный Z** — исходы чередуются.
- **|Z| ≥ 1.96** — порядок неслучаен с вероятностью 95 % (это число в скобках в отчёте).

| Прогон | Z | Вероятность неслучайности |
|---|---|---|
| Окно 12 | −2.68 | 99.3 % |
| 18 | −1.47 | 85.9 % |
| 24 | −2.14 | 96.7 % |
| 30 | −1.93 | 94.6 % |
| 36 | −3.22 | 99.9 % |
| 42 | −1.71 | 91.2 % |
| 48 | −1.19 | 76.7 % |
| 54 | −1.27 | 79.7 % |
| 60 | −1.97 | 95.2 % |
| 24, реальные тики | −1.01 | 69 % |
| Без фильтра, реальные тики | −0.46 | 35 % |
| Без фильтра, OHLC M1 | −3.40 | 99.7 % |

Что это значит для стратегии:
- Сделки зависимы. Для окна 24: вероятность победы после победы 80 %, вероятность убытка
  после убытка 31 % при доле убытков 23 %; максимальная серия побед 15, убытков 3. Победы идут
  сериями на трендовых днях, убытки собираются в боковике.
- Кластеризация есть и без фильтра (на OHLC Z = −3.40), а на реальных тиках без фильтра её нет.
  Значит, она зависит от модели тестера и от входов по фракталам (цепочки разворотов), а не
  создаётся фильтром.
- Значимость по числу сделок завышена: эффективная выборка меньше 365. Поэтому в анализе
  использовались проверки по дням и неделям.
- Просадки в реальности могут быть глубже, чем при независимых сделках.
- Z-score не измеряет прибыльность: самый сильный Z (−3.22) у убыточного окна 36, но и у
  лучших окон Z отрицателен.

## 9. Итоги и открытые вопросы

Что подтверждено:
- Демо и тестер ведут себя одинаково при одинаковых параметрах (сделки совпадают до цента).
- Фильтр тренда улучшает результат по всем окнам 12–60 и в каждом из трёх периодов для окон 12–24.
- Ограничитель просадки с базой «дневной убыток» и порогом 60 лучше прежнего порога 30.

Что не доказано или рискованно:
- Статистическая значимость выигрыша фильтра слабая; цифры для окна 24 завышены выбором.
- Сентябрь–октябрь: все варианты в минусе, стратегия не зарабатывает в боковике.
- Тестер зависит от модели тиков (шум до нескольких сотен долларов за 7 месяцев).
- Механика (lock больше триггера, трейлинг шире тейка) делает стратегию чувствительной к
  винрейту; запас над безубыточным уровнем 2–8 п.п.

План:
1. Продолжить демо-тест на текущем наборе и накопить 50–100 сделок вне выборки; перед каждым
   перезапуском сверять входные параметры.
2. Добавить предупреждения в `OnInit` на `lock ≥ trigger` и `trail ≥ TP`, затем пересмотреть
   диапазоны безубытка и трейлинга и переоптимизировать их по методике walk-forward.
3. Проверить метод Efficiency Ratio (`InpTrendMethod = 1`) как независимое подтверждение
   пользы фильтра.
4. Рассмотреть режим «только логировать» тренд-фильтра для точного учёта отсечённых сигналов.
